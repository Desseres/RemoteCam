# RemoteCam 0.3.3 — Android + Windows public test

Use your Android phone as a camera and optional microphone for your computer.
This combined test release includes **Android 0.3.3** and **RemoteCam Desktop
0.1.10 for Windows** in the same set of assets. Both apps are free to use, with
no ads or subscriptions.

## Downloads

| Asset | Purpose | Requirements |
| --- | --- | --- |
| **RemoteCam-0.3.3.apk** | Camera and microphone sender for your phone | Android 9 or newer |
| **RemoteCam-Desktop-0.1.10-test-Setup.exe** | Windows receiver and virtual camera installer | Windows 11 x64; administrator access for installation |
| **SHA256SUMS.txt** | Checksums for all packaged files | Any SHA-256 utility |
| **android-build-info.json / windows-build-info.json** | Component versions, source commits and build provenance | Text/JSON viewer |

Download the APK on your phone and the EXE on your Windows computer. Android
and Desktop keep their own version numbers; **v0.3.3** identifies this combined
release. The EXE is the same verified 0.1.10 installer previously published in
the Windows-only release.

## Get started with OBS

1. Install the APK. If prompted, allow **Install unknown apps** for the browser
   or file manager used to open it. Grant camera access in RemoteCam.
2. Install the EXE on Windows. It includes the receiver and virtual camera
   component; no separate camera registration script is needed.
3. Connect both devices to the same trusted local network.
4. On the phone, select **H.264 + WebRTC**, start with **1920 × 1080 / 30 fps**,
   and enable **Stream**.
5. In Desktop, enter `PHONE_IP:8080` and click **Połącz** (Connect).
6. In OBS, add **Video Capture Device** and select **RemoteCam**.

You can also receive the phone stream directly through OBS Browser Source or
go2rtc. RemoteCam Desktop is optional for those workflows.

## What is included

### Android 0.3.3

- Optional **H.265 + WebRTC (test)**, alongside H.264, JPEG Browser and MJPEG.
  H.264 remains the recommended WebRTC mode. H.265 requires a compatible hardware
  encoder and receiver; unsupported combinations report an error.
- Hardware video capture and encoding, camera/resolution selection, rotation,
  focus and zoom controls, and saved settings.
- Optional Opus microphone audio and a separate mute control over WebRTC.
  JPEG and MJPEG carry video only.
- Codec negotiation and receiver recovery improvements, including codec changes.
- Updated project attribution in the information screen.

### Windows Desktop 0.1.10

- A Windows virtual camera providing **1920 × 1080 at 30 fps**.
- H.264/H.265 decoding through **D3D11VA GPU acceleration** where available,
  with a CPU fallback and recovery after stream interruptions.
- Tray operation: closing/minimizing the window keeps the stream active and
  suspends preview rendering. **Zakończ** (Exit) in the tray stops the application.
- A hardware/quality panel with observations and suggested starting settings.
- Optional microphone routing through **VB-CABLE**, with gain and mute controls.
- A branded dark interface, application icon, information links, a single EXE
  installer, and corrected microphone/address-field layouts.

## Optional phone microphone

Enable **Microphone audio** on the phone and grant microphone access. In Desktop,
open **Mikrofon** and install VB-CABLE if needed, then enable the microphone.
In OBS, add **Audio Input Capture → CABLE Output** (or its custom device name).
Set monitoring to **Monitor Off** and mute any open phone preview in your browser
to avoid duplicate audio. Keep **Listen to this device** disabled in Windows.

VB-CABLE is a separate VB-Audio product with its own donationware license. Its
installation is optional. Its installer may change Windows default audio devices;
check your speakers and physical microphone afterward. RemoteCam does not route
phone audio to your default speakers or rename system audio devices automatically.

## Updating and compatibility

The APK uses package **pl.remotecam.app**, version code **19**, and the existing
release signing certificate. It can update the signed 0.3.1, 0.3.2 and H.265 test
packages while preserving settings. Debug builds use a different signing key.

Before updating Desktop, choose **Zakończ** from its tray menu. Closing the window
alone leaves it running. The Desktop interface is currently in Polish; this
release description and the main README are in English.

## Test status and limitations

This is a **prerelease for testing**, not a guarantee of performance on every
device. Android release compilation, JVM tests, receiver tests and release lint
were checked for this release. APK signing and alignment are verified during
packaging; asset checksums are verified before publication.

Earlier physical-device tests covered an Honor BVL-N49 running Android 16,
hardware H.264/H.265 reception, the Windows camera API, tray continuity and
VB-CABLE capture/mute/resume. These results are documented in the repository;
they are not a fresh end-to-end latency measurement of this APK.

H.265 support in Desktop does not imply H.265 support in OBS Browser Source.
AV1 is not implemented. Start with H.264 at 1080p; 4K input increases decoding
work even though the virtual camera output remains 1080p. Locked-screen behavior,
audio synchronization and broader device compatibility still need testing.

Desktop runs in your user session, not as a Windows service. Logging out or
exiting stops reception. The RemoteCam EXE installer is not Authenticode-signed;
its SHA-256 checksum is supplied. The APK is signed with the release key.

Use a trusted LAN and do not expose the phone's HTTP port to the internet.
